# Optimización del CI para 1.1.0

Fecha: 2026-10-29

## Cambios

- Los jobs `linux`, `windows` y `macos` solo se ejecutan en tags o mediante
  `workflow_dispatch`. `main` y las pull requests se quedan solo con formato,
  clippy y pruebas.
- Se mantiene un único workflow `.github/workflows/ci.yml`.
- El job `release` sigue ejecutándose solo con tags y conserva los checksums y
  la publicación automática.
- Se añade `Swatinem/rust-cache@v2` a los jobs de pruebas y a los tres builds.
  La clave tiene en cuenta el job, el sistema, la versión de Rust y `Cargo.lock`;
  el `target/` cacheado conserva los builds de cada target instalado.

## sccache

Se evaluó `sccache` para las dependencias C/C++ y no se añadió:

- `rust-cache` ya reutiliza `target/` completo, incluidos los objetos de los
  crates C/C++, cuando la clave coincide.
- Para persistir entre ejecuciones, `sccache` necesitaría un backend remoto o
  el backend de GitHub Actions, con configuración y permisos adicionales.
- NASM, usado por el decodificador AVIF, no pasa por `sccache`.

Se puede reconsiderar si los tiempos de CI siguen siendo altos después de medir
el efecto de `rust-cache`.

## Verificación

- Workflow revisado: pruebas en `main`/PR, builds en tags/manual y release solo
  en tags.
- Validación del cambio por el usuario el 2026-10-30. La ejecución real del
  workflow se hará en la próxima ejecución manual o en el tag de 1.1.0.
